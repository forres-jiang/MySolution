## 已完成的优化

| 方面 | 调整与行为 |
| --- | --- |
| 架构约束 | API 允许引用通用宿主能力，依赖方向检查覆盖 AppHost 与 ServiceDefaults；新增 GitHub Actions 构建与测试流程 |
| 本地编排 | AppHost 将数据库和缓存连接注入应用实际读取的键；密钥通过秘密参数提供；独立迁移进程成功完成后启动 API |
| 可选缓存 | Redis 故障回退数据库，退出就绪探针；完整诊断报告 Degraded；禁用缓存时不注册连接；取消继续向上传递 |
| 授权成本 | 同一作用域内，HTTP 和用例复用用户与角色集合对应的权限快照，并发检查合并读取；身份、角色改变或当前作用域成功修改权限后重新读取 |
| 事务边界 | 菜单、角色菜单、权限用例依赖各自的窄接口；组合用例保留组合接口；各接口共用作用域内同一事务适配器 |
| 菜单排序 | 仅写入位置实际变化的节点，未变节点保留审计字段；变化记录使用同一 UTC 时间 |
| 模型契约 | 核心模型用 required 声明必填字段，姓名、邮箱等可缺省信息按可空类型表达；存储快照验证用户标识长度，保留版本零兼容；领域与应用项目将可空性警告视为错误 |
| 文档与启动入口 | 更新启动配置、密钥准备、探针和授权一致性说明；旧评审与整改计划标注为历史快照 |

## 授权一致性约定

一次请求内采用首次读取的权限快照；其他请求的权限修改在下一次请求重新检查。权限管理和组合写入用例成功后使本作用域快照失效。直接权限查询仍读取存储，不使用授权快照。后台任务应按每次工作建立作用域，避免把作用域当成长时间缓存。
